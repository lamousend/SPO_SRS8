# Проверка запуска с нуля

Цель - убедиться, что проект запускается только по документации. Проверка выполняется на новой копии
репозитория и в новом окружении. Если какого-то шага не хватило, он добавляется в документацию,
и проверка повторяется.

## Автоматическая проверка

```bash
bash scripts/verify_clean_start.sh
```

| Шаг | Что делается | Что проверяется |
|-----|--------------|-----------------|
| 1 | копируются только файлы репозитория, без .env и db.sqlite3 | проекту не нужны локальные файлы |
| 2 | новое окружение и установка requirements.txt (--skip-install - пропустить) | хватает зависимостей |
| 3 | python scripts/make_env.py и check | настройка по образцу работает |
| 4 | migrate | таблицы создаются в пустой базе |
| 5-6 | seed_lab_data и 21 автотест | тестовые данные и правила работы |
| 7-8 | запуск сервера, вход, создание и выдача через API | интерфейс и API работают |
| 9 | перезапуск сервера и повторное чтение данных | данные сохраняются |
| 10 | DJANGO_DEBUG=false, collectstatic, Gunicorn | настройки для Render |

В конце выводится список шагов. Проверка на PostgreSQL:
VERIFY_DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/verify bash scripts/verify_clean_start.sh.
В CI проверка выполняется при каждой загрузке кода ([ci-and-releases.md](ci-and-releases.md)).

## Ручная проверка на Windows

Проект склонирован с GitHub в новую папку SPO_SRS8_check, создано новое окружение (Python 3.12.6)
и пустая база.

| № | Проверка | Результат |
|---|----------|-----------|
| 1 | зависимости ставятся по requirements.txt | Successfully installed |
| 2 | настройка по .env.example | без ключа - ImproperlyConfigured; с ключом - check без ошибок |
| 3 | миграции | все OK |
| 4 | интерфейс | страницы входа и бронирования открываются с оформлением |
| 5 | API | GET - 200, POST - 201, выдача и возврат - 200, выдача сверх остатка - 400 |
| 6 | данные после перезапуска | заявка, бронирование, остаток и история на месте (автоматическая проверка, шаг 9) |
| 7 | типичная ошибка | найдена в [troubleshooting.md](troubleshooting.md), исправление помогло |

## Найденные проблемы

При подготовке документации:

| Проблема | Что исправлено |
|----------|----------------|
| не было описано, как задать ключ локально, файл .env не читался | settings.py читает .env, добавлен make_env.py |
| .env.example был рассчитан только на Render | образец переписан для локальной работы |
| после миграций не было тестовых данных | добавлена команда seed_lab_data |
| README.md был пустым | написан README и папка docs/ |
| requirements.txt был в UTF-16 | файл пересохранен в UTF-8 |
| не было проверки, что все работает | добавлены автотесты и verify_clean_start.sh |

При повторном запуске на Windows:

| Проблема | Что исправлено |
|----------|----------------|
| python вызывал заглушку Microsoft Store | в инструкцию добавлен py -3.12 |
| при ручной правке .env ключом заменили всю строку | добавлен make_env.py и пример строки |
| в .env не хватало переменных | make_env.py проверяет обязательные переменные |
| collectstatic не находил файлы .map из-за переводов строк CRLF | исправлен config/storage.py, добавлен .gitattributes |
| резервная копия сохранялась в кодировке cp1251 | backup_restore.py сохраняет копию в UTF-8 |
