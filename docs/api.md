# REST API

Базовый адрес локально: `http://127.0.0.1:8000`. Полный перечень маршрутов, параметров и полей, созданный
автоматически, — [api-reference.md](api-reference.md); машиночитаемая схема OpenAPI 3.0 — [openapi.json](openapi.json)
(открывается в Swagger Editor или импортируется в Postman). Соответствие реальных ответов схеме проверяют
контрактные тесты `OpenApiContractTests`. Здесь описаны **только реально
реализованные** операции; примеры ответов получены с работающего проекта.

## Общие правила

| Параметр | Значение |
|----------|----------|
| Формат | JSON, заголовок `Content-Type: application/json` |
| Аутентификация | сессия Django (cookie `sessionid`); вход — `/accounts/login/` |
| CSRF | для `POST`, `PUT`, `PATCH`, `DELETE` — заголовок `X-CSRFToken` со значением cookie `csrftoken` |
| Пагинация | не используется: списки возвращаются массивом |
| Без входа в систему | `403`, тело `{"detail": "..."}` (текст зависит от языка) |
| Формат ошибок валидации | `{"поле": ["сообщение"]}` или `{"поле": "сообщение"}`; общая ошибка — массив строк |
| Недоступный объект | `404` — объект не существует, удалён или принадлежит другому пользователю |

Типичные ошибки для всех маршрутов:

| Код | Когда |
|-----|-------|
| 400 | данные не прошли проверку, недопустимый переход состояния |
| 403 | нет сессии или не передан CSRF-токен |
| 404 | объект не найден или чужой |
| 405 | метод не поддерживается маршрутом (например `POST /api/equipment/`) |
| 500 | серверный сбой; интерфейс показывает «Ошибка сервера» |

## Заявки

### GET `/api/categories/` и GET `/api/categories/{id}/`
| Параметр | Описание |
|----------|----------|
| Назначение | справочник категорий заявок (только чтение) |
| Аутентификация | сессия |
| Тело запроса | нет |
| Успех | `200`, `[{"id": 1, "name": "Оборудование"}, ...]` |
| Ошибки | `403` без входа; `404` для несуществующего `{id}` |
| Проверка | Network при открытии страницы заявок: `GET /api/categories/ 200` |

### GET `/api/tickets/`
| Параметр | Описание |
|----------|----------|
| Назначение | свои заявки, новые сверху |
| Аутентификация | сессия |
| Query | `status` = `new` \| `progress` \| `done` (неизвестное значение даёт пустой список) |
| Успех | `200`, массив заявок |
| Ошибки | `403` |
| Проверка | `GET /api/tickets/?status=progress` возвращает только заявки в работе |

### POST `/api/tickets/`
| Параметр | Описание |
|----------|----------|
| Назначение | создать заявку; владелец назначается сервером |
| Аутентификация | сессия + CSRF |
| Тело запроса | `{"title": "Не работает принтер", "description": "Каб. 301", "category": 1}` |
| Успех | `201`, `{"id": 1, "title": "Не работает принтер", "description": "Каб. 301", "category": 1, "category_name": "Оборудование", "status": "new", "created_at": "2026-11-04T12:50:48.688646+03:00"}` |
| Ошибки | `400` `{"title": ["Название должно содержать не менее 5 символов."]}`; `400` если `status` не `new` |
| Проверка | в Network `POST` → `201`; запись видна в `GET /api/tickets/` и после перезапуска |

### GET `/api/tickets/{id}/`
Получение одной своей заявки: `200` с объектом; `404` — не найдена или чужая.

### PATCH `/api/tickets/{id}/`
| Параметр | Описание |
|----------|----------|
| Назначение | смена статуса и/или изменение полей собственной заявки |
| Аутентификация | сессия + CSRF |
| Тело запроса | `{"status": "progress"}` |
| Допустимые переходы | `new → progress`, `progress → done`; остальные запрещены |
| Успех | `200`, JSON обновлённой заявки (`"status": "progress"`) |
| Ошибки | `400` `{"status": ["Недопустимый переход статуса."]}`; `404` |
| Проверка | `PATCH {"status": "new"}` для заявки в работе → `400`, статус в БД не меняется |

### PUT `/api/tickets/{id}/`
Полная замена: обязательны `title` и `category`; правила переходов те же. Интерфейс использует `PATCH`.

### DELETE `/api/tickets/{id}/`
Удаление своей заявки: `204` без тела; `404` — чужая или не существует.

## Бронирование оборудования

### GET `/api/equipment/` и GET `/api/equipment/{id}/`
| Параметр | Описание |
|----------|----------|
| Назначение | оборудование и остатки (только чтение; добавление — через `/admin/`) |
| Успех | `200`, `[{"id": 1, "name": "Проектор", "total_q": 2, "available_q": 2}, ...]` |
| Ошибки | `403`; `404` для `{id}`; `405` на запись |

### GET `/api/reservations/`
| Параметр | Описание |
|----------|----------|
| Назначение | свои неудалённые бронирования, новые сверху |
| Query | `status` = `created` \| `issued` \| `returned`; `equipment` = числовой id оборудования |
| Успех | `200`, массив бронирований |
| Ошибки | `400` `{"equipment": "Некорректный ID оборудования"}` для нечислового или нулевого `equipment`; неизвестный `status` — пустой список |
| Проверка | `GET /api/reservations/?status=issued&equipment=1` возвращает только выданные проекторы |

### POST `/api/reservations/`
| Параметр | Описание |
|----------|----------|
| Назначение | создать бронирование (остаток не уменьшается) |
| Аутентификация | сессия + CSRF |
| Тело запроса | `{"purpose": "Практическая работа", "equipment": 1, "quantity": 2}` |
| Успех | `201`, `{"id": 1, "purpose": "Практическая работа", "equipment": 1, "equipment_name": "Проектор", "quantity": 2, "status": "created", "created_at": "..."}`; в историю добавляется событие `created` |
| Ошибки | `400` `{"quantity": ["Количество должно быть больше нуля"]}`; `400` короткое назначение; `400` при передаче `status` или `owner` |
| Проверка | запись и событие появляются в БД; остаток оборудования прежний |

### GET `/api/reservations/{id}/`
`200` с объектом; `404` — не найдено, удалено или чужое.

### PATCH `/api/reservations/{id}/` и PUT `/api/reservations/{id}/`
| Параметр | Описание |
|----------|----------|
| Назначение | изменить сведения о бронировании в состоянии `created` |
| Тело запроса | `{"quantity": 2}` (для `PUT` — все поля) |
| Успех | `200`, обновлённый объект; событие `edited` |
| Ошибки | `400` «Редактировать можно только созданное бронирование»; `404` |

### DELETE `/api/reservations/{id}/`
| Параметр | Описание |
|----------|----------|
| Назначение | «мягкое» удаление: заполняется `deleted_at`, запись скрывается, история остаётся |
| Успех | `204`, событие `deleted` |
| Ошибки | `400` `["Удалить можно только созданное бронирование."]` для `issued`/`returned`; `404` |

### POST `/api/reservations/{id}/issue/`
| Параметр | Описание |
|----------|----------|
| Назначение | выдать оборудование: `created → issued`, `available_q -= quantity` (одна транзакция) |
| Аутентификация | сессия + CSRF |
| Тело запроса | нет |
| Успех | `200`, бронирование со `status: "issued"`; событие `issued` |
| Ошибки | `400` `{"status": "Выдать можно только созданное бронирование"}` (повторная выдача); `400` `{"quantity": "Недостаточно доступного оборудования"}`; `404` |
| Проверка | остаток уменьшился, в `/history/` три события; при отказе остаток и история не меняются |

### POST `/api/reservations/{id}/return_equipment/`
| Параметр | Описание |
|----------|----------|
| Назначение | вернуть оборудование: `issued → returned`, `available_q += quantity` |
| Успех | `200`, `status: "returned"`; событие `returned` |
| Ошибки | `400` `{"status": "Вернуть можно только выданное оборудование."}`; `400` «Возврат превысил бы общий остаток.»; `404` |

### GET `/api/reservations/{id}/history/`
| Параметр | Описание |
|----------|----------|
| Назначение | история событий бронирования по возрастанию времени |
| Успех | `200`, `[{"id": 1, "action": "created", "action_name": "Создание", "actor_name": "student1", "details": "Бронирование создано", "created_at": "..."}, ...]` |
| Ошибки | `404` — чужое или удалённое бронирование |

## Пример вызова из консоли браузера

```js
const csrf = document.querySelector('[name=csrfmiddlewaretoken]').value;
const r = await fetch('/api/reservations/1/issue/', {
  method: 'POST', credentials: 'same-origin',
  headers: {'Content-Type': 'application/json', 'X-CSRFToken': csrf},
});
console.log(r.status, await r.json());
```

Для скриптов вне браузера см. `scripts/smoke_api.py`: он входит через форму `/accounts/login/`,
затем отправляет запросы с cookie и CSRF-заголовком. Пароли и токены в документацию не вставляются.
