# REST API

Адрес при локальном запуске: http://127.0.0.1:8000. Здесь описаны только реальные маршруты,
примеры ответов взяты из работающего проекта. Полный справочник создается автоматически -
[api-reference.md](api-reference.md), схема OpenAPI - [openapi.json](openapi.json).

## Общие правила

| Параметр | Значение |
|----------|----------|
| Формат | JSON |
| Вход | сессия Django, страница /accounts/login/ |
| CSRF | для POST, PUT, PATCH и DELETE нужен заголовок X-CSRFToken со значением cookie csrftoken |
| Списки | возвращаются массивом, без страниц |

| Код | Когда |
|-----|-------|
| 400 | неверные данные или запрещенное действие |
| 403 | нет входа или нет CSRF-токена |
| 404 | объект не найден, удален или чужой |
| 405 | метод не поддерживается |
| 500 | ошибка сервера, на странице - «Ошибка сервера» |

## Заявки

### GET /api/categories/ и GET /api/categories/{id}/
| Параметр | Описание |
|----------|----------|
| Назначение | список категорий, только чтение |
| Ответ | 200, [{"id": 1, "name": "Оборудование"}, ...] |
| Ошибки | 403 без входа; 404 для неизвестного id |

### GET /api/tickets/
| Параметр | Описание |
|----------|----------|
| Назначение | свои заявки, новые сверху |
| Фильтр | status = new, progress или done |
| Ответ | 200, массив заявок |
| Ошибки | 403 |

### POST /api/tickets/
| Параметр | Описание |
|----------|----------|
| Назначение | создать заявку; владельца задает сервер |
| Тело | {"title": "Не работает принтер", "description": "Каб. 301", "category": 1} |
| Ответ | 201, {"id": 1, "title": "Не работает принтер", "description": "Каб. 301", "category": 1, "category_name": "Оборудование", "status": "new", "created_at": "..."} |
| Ошибки | 400 {"title": ["Название должно содержать не менее 5 символов."]}; 400, если status не new |

### GET /api/tickets/{id}/
Одна своя заявка: 200 с объектом; 404, если заявки нет или она чужая.

### PATCH /api/tickets/{id}/
| Параметр | Описание |
|----------|----------|
| Назначение | сменить статус или поля своей заявки |
| Тело | {"status": "progress"} |
| Разрешено | new - progress, progress - done |
| Ответ | 200, обновленная заявка |
| Ошибки | 400 {"status": ["Недопустимый переход статуса."]}; 404 |
| Проверка | {"status": "new"} для заявки в работе дает 400, статус не меняется |

### PUT /api/tickets/{id}/
Полная замена заявки, обязательны title и category. Правила статуса те же.

### DELETE /api/tickets/{id}/
Удалить свою заявку: 204 без тела; 404, если заявка чужая или ее нет.

## Бронирование оборудования

### GET /api/equipment/ и GET /api/equipment/{id}/
| Параметр | Описание |
|----------|----------|
| Назначение | оборудование и остатки, только чтение |
| Ответ | 200, [{"id": 1, "name": "Проектор", "total_q": 2, "available_q": 2}, ...] |
| Ошибки | 403; 404 для неизвестного id; 405 при попытке записи |

### GET /api/reservations/
| Параметр | Описание |
|----------|----------|
| Назначение | свои бронирования, новые сверху |
| Фильтры | status = created, issued или returned; equipment = id оборудования |
| Ответ | 200, массив бронирований |
| Ошибки | 400 {"equipment": "Некорректный ID оборудования"} для equipment=abc или 0 |
| Проверка | /api/reservations/?status=issued&equipment=1 возвращает только выданные проекторы |

### POST /api/reservations/
| Параметр | Описание |
|----------|----------|
| Назначение | создать бронирование; остаток пока не меняется |
| Тело | {"purpose": "Практическая работа", "equipment": 1, "quantity": 2} |
| Ответ | 201, бронирование со статусом created; в историю пишется событие created |
| Ошибки | 400 {"quantity": ["Количество должно быть больше нуля"]}; 400 для короткого назначения; 400, если передан status или owner |

### GET /api/reservations/{id}/
Одно свое бронирование: 200; 404, если его нет, оно удалено или чужое.

### PATCH /api/reservations/{id}/ и PUT /api/reservations/{id}/
| Параметр | Описание |
|----------|----------|
| Назначение | изменить бронирование в состоянии created |
| Тело | {"quantity": 2} |
| Ответ | 200, событие edited |
| Ошибки | 400 «Редактировать можно только созданное бронирование»; 404 |

### DELETE /api/reservations/{id}/
| Параметр | Описание |
|----------|----------|
| Назначение | скрыть бронирование, история остается |
| Ответ | 204, событие deleted |
| Ошибки | 400 «Удалить можно только созданное бронирование.»; 404 |

### POST /api/reservations/{id}/issue/
| Параметр | Описание |
|----------|----------|
| Назначение | выдать оборудование: статус created меняется на issued, остаток уменьшается |
| Тело | нет |
| Ответ | 200, бронирование со статусом issued; событие issued |
| Ошибки | 400 {"status": "Выдать можно только созданное бронирование"}; 400 {"quantity": "Недостаточно доступного оборудования"}; 404 |
| Проверка | остаток уменьшился, в истории новое событие; при ошибке ничего не меняется |

### POST /api/reservations/{id}/return_equipment/
| Параметр | Описание |
|----------|----------|
| Назначение | вернуть оборудование: статус issued меняется на returned, остаток увеличивается |
| Ответ | 200, статус returned; событие returned |
| Ошибки | 400 {"status": "Вернуть можно только выданное оборудование."}; 404 |

### GET /api/reservations/{id}/history/
| Параметр | Описание |
|----------|----------|
| Назначение | история бронирования по времени |
| Ответ | 200, [{"id": 1, "action": "created", "action_name": "Создание", "actor_name": "student1", "details": "Бронирование создано", "created_at": "..."}, ...] |
| Ошибки | 404 |

## Пример запроса из консоли браузера

```js
const csrf = document.querySelector('[name=csrfmiddlewaretoken]').value;
const r = await fetch('/api/reservations/1/issue/', {
  method: 'POST', credentials: 'same-origin',
  headers: {'Content-Type': 'application/json', 'X-CSRFToken': csrf},
});
console.log(r.status, await r.json());
```

Пример для скриптов - scripts/smoke_api.py. Пароли и токены в документацию не вставляются.
